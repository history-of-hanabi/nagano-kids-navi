サイトの位置付け
長野市キッズナビは「塾検索サイト」ではありません。長野市の保護者に寄り添う地域教育メディアです。

目的は施設を比較・検索・紹介することではなく、保護者がお子さまに合った学びを一緒に考えられるよう支援することです。

ブランドメッセージ
トップページで確立したブランドコピーを全ページの基準とします（プロジェクト憲章4節と同一）。

Hero：長野市で、お子さまに合った学びを、一緒に考える。 Lead：学び方から相談先まで、お子さまに合った学びを考えるヒントをお届けします。

今後制作するページも、この世界観を崩さないこと。

サイトの立場・基本トーン
このサイトは「正解を教えるサイト」ではなく「一緒に考えるサイト」です。答えを断定するのではなく、保護者が判断するための情報・選択肢・ヒントを提供します。

文章は「寄り添う／押し付けない／断定しない／安心感がある」ことを最優先します。

ナビゲーションだけは例外
「探す」はナビゲーション機能として使用可（プロジェクト憲章7節参照）。

例：今のお困りごとから探す／学び方から探す／相談先を探す／条件から探す

これは機能ラベルであり、ブランドコピーとは役割が違うため問題ない。

学び方ガイドの考え方
学び方を「個別指導／集団指導」で分類しない。代わりに「学校／家庭／地域／民間」など教育全体の選択肢として扱う。

※「学校」の語がサイト設計書5・6節で2つの異なる意味に使われている点に注意（学びの場としての学校／相談窓口としての学校）。

診断ページの設計思想
名称は「学び方診断」で統一。「学習スタイル診断」は使用しない。

診断結果は「あなたに最適です」とは書かない。必ず「考えるためのヒント」として提示する。

例：

診断結果は、お子さまに合った学びを考えるためのヒントです。実際の選択は、お子さまの様子やご家庭の状況も踏まえて考えていきましょう。

学年・地域（ages / areas）を扱う際の注意（v1.1追加）
ages・areasは独立ハブページではなく、worries／methods／institutions／glossaryの記事に付与する横断的な絞り込み条件（タグ）です（サイト設計書7・8節参照）。

記事を書く際は、必ず主カテゴリ（4つのいずれか）を1つ決めたうえで、必要に応じて学年タグ・地域タグを付与すること。学年別・地域別に同内容の記事を複製しない。

記事ページの考え方
記事は「答え」を書くのではなく、保護者が理解を深められる内容を書く。

記事のゴールは「理解する／考える／相談先を知る」である。

Aboutの役割
Aboutは「サイトでできること」を説明する場所。現在の表現を基準とする。

お子さまの悩みについて理解を深められる
お子さまに合った学びについて考えられる
相談先・支援機関がわかる
教育に関する言葉や制度について理解できる

記事構成テンプレート（v1.2追加）
記事は必ず、扱うハブに対応する型のテンプレートに沿って制作する。共通ルールとして、CTAは記事末尾に1個のみ（本文中CTA禁止）。内部リンクは目安として最大4（関連記事3＋次に読む記事1）。FAQは5〜8問とし、実運用では6問で統一している。FAQ本文とJSON-LD（FAQPage構造化データ）は、HTMLタグを除去した文字列として完全に一致させること。

glossary型（教育の基礎知識）

Hero → 公開状況の告知バー → 導入（共感） → 結論（summary-box） → 詳しい説明（h3を2つ：定義・分類／なぜこの言葉が使われるのか） → よくある誤解（warning-card） → 関連する言葉との違い（compare-table、2列、末尾に相談導線の一文を添える） → FAQ → 次に読む記事（related-link-box） → CTA

診断・原因の特定は行わない。断定を避け「〜とされています」「〜ことがあります」を一貫して用いる。DSM-5等の詳細な診断基準には立ち入らず、教育の文脈で使われる言葉としての説明にとどめる。

worries型（お悩み別ガイド）

Hero（導入） → 結論（summary-box） → 共感 → 理由・根拠（h3を2つ） → 具体例（point-card、よくある様子の例。診断的な断定を避ける一文を添える） → メリット・デメリット比較（compare-table、対応の比較） → FAQ／反論への回答（保護者が抱きやすい迷いに回答する形式） → 今日からできること（point-card） → 次に読む記事 → CTA

glossary型のFAQ（用語理解の補足）とは目的が異なり、worries型のFAQは「保護者の不安や迷いを和らげること」を目的とする。

methods型（学び方ガイド）

Hero → 結論（summary-box） → この学び方とは（対象範囲の定義を最初に明確化） → 特徴・向いているケース／よく利用される例（point-card） → メリット・デメリット（compare-table、2列） → 利用までの流れ（info-box＋<ol>。「利用開始」という概念がない学び方（学校・家庭など）は「学びを活かすためにできること」等、実態に合わせて柔軟に読み替える） → FAQ → 次に読む記事 → CTA

特定の民間サービス名・企業名は出さない。学び方を断定的に評価・推奨しない。

institutions型（相談先・支援機関）

Hero → 結論（summary-box） → 〇〇とは（役割・対象範囲） → 特徴・向いているケース（point-card） → メリット・デメリット（compare-table） → 相談までの流れ（info-box＋<ol>：気になる → 相談 → 見学・面談 → 利用開始） → FAQ → 次に読む記事 → CTA

自治体・学校によって扱いが異なる事項（出席扱い、費用、利用条件等）は断定せず、「学校や自治体の窓口にご確認ください」という形でヘッジする。

公開前品質チェックリスト（v1.2追加）
新規記事・修正記事は、公開前に以下を確認する。

FAQ本文とJSON-LD（FAQPage）が完全一致している（タグ除去後の文字列比較）
canonical が設定されている
title・description が設定されている
BreadcrumbList構造化データが実装されている
FAQPage構造化データが実装されている
CTAボタンが1個のみである
内部リンクがすべて公開済みページ、または実在するアンカーである（404がない）
sitemap.xml に追加されている
禁止語彙（プロジェクト憲章6節）が含まれていない
footerが現行の運用ルール（後述）と一致している

公開時のルール（成果物基準）（v1.2追加）
記事HTMLファイルとsitemap.xmlは、同一コミット・同一pushで公開する。記事ファイルだけを先行してpushし、sitemap.xmlの更新を後回しにしない。
sitemap.xmlには、実際に公開済み（404にならない）ページのみを掲載する。未実装のページ（現時点ではarticles/index.html・diagnosis.html等）へのURLは含めない。
sitemap.xmlのlastmodは、実際に公開・更新した日付を記載する。

footer運用ルール（v1.2追加）
articles/index.html・diagnosis.htmlが未実装の間、全ページのfooterからこの2つへのリンクを外し、「掲載をご希望の教育機関様はこちら」のリンクのみを残す。footer内には、以下の復帰用コメントを設置する。

<!--
  現在は未公開ページのためリンクを外しています。
  以下のページ公開後に footer へ復帰してください。
  ・記事一覧　../articles/index.html（トップページは articles/index.html）
  ・学び方診断　../diagnosis.html（トップページは diagnosis.html）
-->

articles/index.html・diagnosis.htmlを実装・公開した際は、全ページ一括でfooterのリンクを復帰させる。

HTMLコメントの書き方（v1.2追加）
HTML制作方針（本ガイドライン内、既存）で定めた「変更履歴ではなく設計意図を書く」という方針を維持しつつ、記事本文コンポーネントについては簡潔な定型コメントで統一する。

<!-- 結論：summary-box（green） -->
<!-- 共感：worries型テンプレート -->
<!-- FAQ（反論への回答）：faq（green） -->

ページ全体の構造に関わる部分（Hero、ハブ設計との関係、将来の拡張方針など）は、従来どおり設計意図を含めた詳しめのコメントを残してよい。

AI制作時の最優先事項
新しいページを制作するときは、デザインやSEOより先に、以下を満たしているか確認する。

禁止語彙になっていないか（プロジェクト憲章6節を参照）
保護者に寄り添う文章になっているか
「答え」ではなく「考えるヒント」を提供しているか
トップページのブランドコピー「一緒に考える」と矛盾していないか
教育メディアとして自然な文章になっているか
ages/areasを独立ハブとして扱っていないか（v1.1追加）

この6項目を満たさない文章は修正対象とする。
